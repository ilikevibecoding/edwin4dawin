### 2.1 Exhaustive verification: all forests `n <= 22`, multi-component forests `n = 23, 24`, all trees `n <= 28`

`run_forests.py` (Python, exact integers) enumerated every unlabeled forest with
`n <= 22` vertices (21,539,988 forests; 13,184,156 at `n = 22`) and every
forest with at least two components on `n = 23` (19,574,858) and `n = 24`
(51,028,777) vertices.  `fast/wromcheck.c` (C, `__int128`) enumerated every
tree with `n <= 28` vertices (3,222,181,088 trees in all; 2,023,443,032 at
`n = 28`).  The two implementations agree exactly on all 9,114,285 trees with
`n <= 22`.

| check | all forests `n <= 22`, multi-component `n = 23, 24` | all trees `n <= 28` |
|---|---|---|
| `UNIMODAL` | holds | holds |
| `LC` (log-concave) | holds | **fails: exactly 2 trees at `n = 26`, 0 at `n = 27`, 19 at `n = 28`**; none at `n <= 25` |
| `ISO_r`, all `1 <= r <= alpha-1` | holds | holds |
| `ISO_r`, prefix `2 <= r <= L-1` | holds | holds |
| `NW_r` (`r p_r^2 >= (r+1) p_{r-1} p_{r+1}`), all `r` | holds | **fails: 1 tree at `n = 24`, 4 at `n = 26`, 30 at `n = 28`**; 0 at `n <= 23, 25, 27` |
| `NW_r`, prefix only | holds | holds (`n <= 26`; not recorded separately for `n = 27, 28`) |
| `WR_r` on the prefix | holds | holds |
| `TAIL` (`p_r >= p_{r+1}` for `r >= L`) | holds | holds |

Reports: `reports/forests_nNN.json`, `reports/forests_multi_nNN.json`,
`reports/trees_nNN.json` (Python, `n <= 22`), `reports/trees_c_*.jsonl` (C),
`reports/forests_summary.json`, with SHA256 in `reports/MANIFEST.sha256.json`.
Every Python report carries an order-independent hash of the multiset of
coefficient vectors, so a re-run on other hardware can be compared bit-for-bit.

The two log-concavity failures at `n = 26` are exactly the two trees `3,4,4`
and `3*,3,4` of Kadrawi–Levit–Yosef–Mizrachi (2023), and the counts `0` at
`n = 27` and `19` at `n = 28` match the public record (erdosproblems.com forum,
2026) — an end-to-end consistency check of the enumeration and the arithmetic
against independent published computations.
The weakened Newton failures (`3,3,4` at `n = 24`, at `r = alpha - 1`) are new
data: they show the `p_{r-1}^2` term of `ISO` cannot be dropped in the tail,
and (since real-rooted polynomials satisfy Newton's inequalities) that this
24-vertex tree has non-real roots — sympy's Sturm count gives 3 real roots of 13.

`NW_r` is exactly the *ordered log-concavity* of Basit & Galvin
(arXiv:2006.12562, Question 1.9: `a_k^2 >= (1 + 1/k) a_{k-1} a_{k+1}`,
equivalently the average extension count `e_k` is weakly decreasing).  They
report that Radcliffe verified it for all trees on `<= 25` vertices.  Our
exhaustive run finds that it holds for all trees on `<= 23` vertices and fails
for exactly one tree on 24 vertices, the Kadrawi–Levit-type tree `3,3,4`
(centre `v0` adjacent to `v1, v2, v3` carrying 4, 3, 3 pendant `P_2`'s):
`I = ((1+2x)^4 + x(1+x)^4)((1+2x)^3 + x(1+x)^3)^2 + x(1+2x)^{10}`, coefficients
`[1, 24, 253, 1553, 6193, 16912, 32389, 43650, 40711, 25144, 9348, 1653, 42, 1]`,
with `42^2 = 1764 < (13/12) * 1653 = 1790.75` (so `e_11 = 12*42/1653 < e_12 = 13/42`)
while the sequence *is* log-concave.  The polynomial was recomputed by four
independent methods (rooted DP in Python and in C, the closed-form product
above via sympy, and direct enumeration of the 177,000 independent sets).  So
Question 1.9 has a negative answer already at `n = 24`, two vertices below the
first log-concavity failures; the `n <= 25` verification cited by Basit–Galvin
must have used a different convention or is in error.  (The two 26-vertex
non-log-concave trees also answer 1.9 negatively, since ordered log-concavity
implies log-concavity.)

This extends the handoff's order-8/9/10 finite collars for the *target*
inequality `ISO` to `n <= 22` on the whole forest class and to `n <= 28` on
trees.  It is falsification evidence only (rule 4).  Had a single cell been
negative, the `WR+ISO+TAIL` route would have been dead; none is.

### 2.3 The `WR+ISO+TAIL` logic (`lemma_check.py`)

- Identity `r b^2 + a^2 - (r+1) a b = (r b - a)(b - a)` (and its ratio form
  `r x + 1/x - (r+1) = (r x - 1)(x - 1)/x`) verified symbolically with sympy.
- Descent lemma: `WR_r`, `ISO_r`, `p_{r-1} >= p_r  =>  p_r >= p_{r+1}`.  This is
  a two-line consequence of the identity (proof written out in the docstring);
  it is additionally checked exhaustively on an integer grid.  `WR_r` is
  genuinely needed (`(r,a,b,c) = (1,4,1,2)` satisfies `ISO_1` and `a >= b` but
  not the conclusion).
- Assembly: `TAIL` + (`WR_r`, `ISO_r` for `2 <= r <= L-1`) `=>` unimodal,
  including plateaus and the boundary case `r0 = L` (prose proof in the
  docstring; brute-force check on all small sequences satisfying the
  hypotheses).  Both prefix endpoints are necessary: dropping `r = 2` or
  `r = L-1` from the hypotheses admits non-unimodal sequences.

Hence the open content of the route is exactly: `ISO_r` (and `WR_r`) for all
forests and all `2 <= r <= L(alpha)-1`.  `ISO_r` for `r >= L` and `WR_r`
outside the prefix are *not* needed.

### 2.4 A small exact closure: `ISO_2` for every forest (`iso2_theorem.py`)

With `m = |E|`, `P_2 = sum_v C(d_v,2)`: `p_2 = C(n,2) - m`,
`p_3 = C(n,3) - m(n-2) + P_2`, `P_2 <= C(m,2)`, and
`Q_2 >= f(m) := 2(C(n,2)-m)^2 + n^2 - 3n(C(n,3) - m(n-2) + C(m,2))`, which is
concave in `m` with `f(0) = n^2(n+1)/2 > 0` and `f(n-1) = 2n^2 - 3n + 2 > 0`.
Identities verified symbolically; counting formulas verified on all forests
`n <= 11`.  (This is the `r = 2` prefix cell; it is likely subsumed by the
handoff's frozen rank-4 foundation, but it is independent of it.)

### 2.5 Extremal structure of `ISO` (informative for any certificate)

The tightest `ISO_r` cell (minimum of `Q_r / ((r+1) p_{r-1} p_{r+1})`) depends
on both `r` and `n`; the argmin family *migrates* as `n` grows.  From the
reports (`iso_min_by_r`):

Over **all forests**:

- `r = 2`: the star `K_{1,n-1}` for every `6 <= n <= 22` (ratio `~ 4/n^2`);
- `r = 3`: the empty forest for `n <= 11`, then `K_{1,n-3} + 2K_1` (`n = 12..14`),
  `K_{1,n-4} + 3K_1` (`15..19`), `K_{1,n-5} + 4K_1` (`20..22`);
- `r = 4`: the empty forest for `n <= 19`, then `K_{1,n-8} + 7K_1` (`20..22`);
- `r >= 5`: the empty forest for all `n <= 22` (by the pattern above, a switch
  to star-plus-isolates is expected at larger `n`).

Over **trees**:

- `r = 2`: the star for every `n <= 28`;
- `r = 3`: the star for `n <= 16`, then a "double broom" — a middle vertex
  adjacent to the centres of two stars `K_{1,a}`, `K_{1,b}` with `b` small
  (`(a,b) = (13,2)` at `n = 18`, `(16,3)` at `22`, `(21,4)` at `28`);
- `r = 4, 5`: the star for `n <= 18` (`r = 4`) / `n <= 20` (`r = 5`), then the
  balanced double broom (`(a,b) = (13,12)` at `n = 28`);
- `r = 6`: the star for `n <= 25`, then the balanced double star (two adjacent
  centres, `n = 26..28`);
- `r >= 7`: the star for all `n <= 22` (not tabulated separately beyond).

All tight families are near-binomial (stars, stars plus isolates, double
brooms/stars, the empty forest); the minimum ratio decreases slowly with `n`
and tends to `0` along these families for each fixed `r` (`extremal_families.py`).
Any universal certificate for `ISO` must therefore be exact on these families —
a relaxation that loses even second-order terms in `n` will be infeasible.
This is consistent with, and a plausible explanation for, the sequence of cone
infeasibilities listed in handoff Section 9.

### 2.6 Known non-log-concave families do not threaten the route (`known_counterexamples.py`)

Log-concavity of tree independence polynomials is false (Kadrawi–Levit 2023;
Galvin 2025; Ramos–Sun 2025 — see the literature refresh).  The route does not
use log-concavity, and in the descending region `ISO_r` is weaker than `LC_r`.
`known_counterexamples.py` builds the Kadrawi–Levit families `3,k,k+j`,
`3*,k,k+j` (to `n = 178`) and Galvin's `T_{m,t}` (to `n = 301`), reproduces the
published `I(T1;x)` exactly, and finds: every log-concavity break lies in the
tail `r >= L(alpha)`; `ISO_r` holds for every `r`; `WR` holds on the prefix.
So everything currently known about log-concavity failures is compatible with
`WR+ISO+TAIL`.

### 2.7 Caution for the "component convolution" fallback (handoff Section 10.6)

Unlike log-concavity (Hoggar's theorem), `ISO` is **not** closed under products
of positive sequences: `[1,14,1,4]` and `[1,11,27,37]` both satisfy `ISO_r` for
all `r`, but their product does not.  (In 2·10^5 random trials no product of two
sequences that are both log-concave *and* `ISO` failed prefix-`ISO`; that is only
evidence.)  Any convolution proof of the forest case must therefore carry shape
information about the components beyond `ISO` itself.
