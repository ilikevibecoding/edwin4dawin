# WP-011 — Map architecture & environmental composition (Fable 2)

Graybox → art-directed finish pass for the Northstar Administrative Center. Layout data
(`src/map/layout.js`) is untouched: no room rect, opening position, or stair topology changed.
Everything below is build-time procedural geometry keyed off the locked layout.

## What changed

### New modules (all inside `src/map/`)

| File | Purpose |
| --- | --- |
| `kit.js` | Merged-geometry collector: buckets every finish geometry per material, emits ONE mesh per material via `BufferGeometryUtils.mergeGeometries`. Also the wedge (snow drift) primitive and the collider helper. |
| `mapmaterials.js` | All new material names, registered through `registerMaterialOverrides()` — see "Material names for Fable 3" below. |
| `finish.js` | Interior finish kit: baseboards, door casings/architraves, window stools + aprons, exec crown, wood/tile wainscot, structural columns, EXIT signs. Walks the same wall-segment + opening data the builder uses, so trim always follows the real walls. |
| `ceilings.js` | Acoustic T-bar grid (world-aligned 0.6/1.2 m), stained/missing tile variants in service rooms, recessed troffers + suspended strips + pendants whose XZ positions come from `fixturePlan()` in `lightplan.js` (fixtures == light sources), exposed-deck kit (painted beams, duct runs, conduit) in garage/loading/mech/server/service. |
| `atrium.js` | Hero treatment: Northstar Dynamics feature wall (geometry star + emissive + canvas wordmark), lobby floor inlay banding + compass medallion, architectural planters, suspended ring-light feature under the skylight. |
| `snowscape.js` | Exterior: facade reveal lines + floor band + mullion caps, parapet caps w/ snow, entrance canopy, snow drifts/mounds/plow banks, plaza kit (plowed path, bollards, flagpoles, bench, bike rack, signage monolith), loading apron (markings, dock bumpers, canopies, signage, bollards), courtyard kit, distant lit-window silhouettes + treeline. |

### Modified (my domain)

- `builder.js` — creates the shared `Kit`, calls the new build passes, refined `buildOpening`
  (transom rail at door-head line on tall glass, frosted privacy band on conference glass,
  sill caps), registers all WP-011 assets.
- `structures.js` — `stairFinish()`: stringers, wall handrails, safety-yellow nosing, cage
  rails on open edges, floor-number signage, vapor-tight wall packs. `railingRun()` gained a
  wood-cap option (atrium rails get it, stair shafts stay metal). Dead fence code removed
  (site walls already exist; `snowscape.js` dresses them). Roof gets snow patches.
- `lightplan.js` — extracted `fixturePlan()` (single source of truth for fixture/fill
  positions), added `ACCENTS` (server rack-glow, break/exec warm accents, brand-wall wash),
  EXIT-sign glow points over egress doors. Fill-budget (nearest-N enablement) untouched.
  Sun intensity tuned 3.2 → 2.6 (interiors were clipping to white where the low winter sun
  rakes in — stairwell tops, exec crown, the brand wall; exteriors still read bright).
  Stair shafts (rooms with `ceilMat: 'none'`) get two wall-pack-aligned fills instead of a
  floating mid-air grid; stair-top rooms run at reduced fixture intensity.
- `doors.js` / `glass.js` — no functional change; consumed as-is.

## Performance

Merged static geometry per material: the whole finish pass adds a fixed number of draw calls
(~1 per material name in use, ~45 total for all trim/ceiling/exterior work combined) instead
of thousands of small meshes. Decorative trim casts no shadows where it can't matter
(baseboards, snow caps, reveals are `castShadow: false`).

Numbers from `window.__qa.perf()` at the heaviest checkpoints (`map-perf` scenario,
`artifacts/shots/map-perf.json`):

| Checkpoint | Draw calls | Triangles |
| --- | --- | --- |
| plaza-spawn | 1397 | 382k |
| lobby | 811 | 297k |
| mezz-south | 1199 | 361k |
| cubes | 1043 | 327k |
| garage | 675 | 272k |
| server | 671 | 273k |
| exec-corr | 1186 | 351k |
| courtyard | 1414 | 382k |

These are WHOLE-SCENE numbers (props + characters + viewmodel included; the props pass landed
in parallel and dominates the triangle count). The map's own contribution is **50,150 tris /
200 meshes** (82 merged opaque buckets + 118 individual transparent glass panes; measured
headless via the nav-lab harness). A post-build merge pass (`builder.js#mergeStaticMeshes`)
collapses the ~1,100 individual graybox boxes (wall runs, frames, mullions, steps, rail posts)
into one mesh per material — before/after on identical hero cameras: exec corridor 2497 → 1186
calls, atrium 2297 → ~1200, garage 2486 → 675. Transparent glass is intentionally left
unmerged (per-object depth sorting).

## UV / tiling contract

Every merged finish mesh runs through `worldUVs(geo, scale)` before merge, so the parallel PBR
upgrade tiles correctly with no map-side changes. Exceptions (native UVs, flagged in the kit
with `uv: 0`): canvas signage panels, the logo star, the distant city shells (windows tile at
storey scale via `worldUVs(geo, ~2.6)`).

## Known issues / requests

1. **`ImageData` in nav-lab** — `tools/nav-lab.js` is shared (not mine to edit); it imports the
   map, which now builds canvas signage. Under plain Node this needs the one-line `ImageData`
   stub above. Request: whoever owns `tools/` add the stub to nav-lab's DOM shim.
2. **Planter soil is bare** — plants are Fable 3/props scope (planter locations are in the
   manifest under `ARCH-PLANTER`).
3. **Props overlap risk** — columns at open office (7,7.5)/(14,7.5)/(21,7.5), lobby (14,30),
   garage (7,7.5)-ish and loading; planter AABBs in the manifest. Props agent should place desks
   around them (props weren't placed yet when this landed).
4. **Shared dev-server reloads** — long captures on 5173 get interrupted by other agents'
   saves; `tools/capture-map.js` self-heals but a quiet window makes runs much faster.
5. **No scene environment map** — with metalness > ~0.4 and no env map, faces away from the
   point fills render pure black under the hemisphere light (was visible on duct undersides
   and the canopy soffit). All map materials now keep metalness <= 0.35 as a workaround.
   Request to Fable 3: if the PBR pass adds `scene.environment`, the service metals
   (`ductMetal`, `conduitMetal`, `canopySteel`, `stringerMetal`, `cageMetal`,
   `flagpoleMetal`, `mullionCap`, `bollardMetal`) can get their metalness back.
   Heads-up: the prop cable trays (`PROP-CABLE-TRAY`, e.g. mech room ceiling) show the same
   symptom — they render pure black from below (see `map-rooms--mech.png`, upper left).
6. **Shared capture harness timeouts (affects every agent, not just me)** — with the full art
   pass in the scene (~350k tris / 700–1400 draw calls incl. props + characters + PBR
   textures), one in-game `page.screenshot` takes **49–61 s** under SwiftShader (measured
   3 consecutive shots on an otherwise idle VM). `tools/capture.js` leaves Playwright's
   implicit **30 s** default in place, so every in-game shot now fails on wall clock even
   though the scenario logic passes — and menu-flow's explicit 8 s deploy→playing wait is
   similarly stale (one rendered frame takes seconds). Other agents are hitting the same
   wall (observed fable1/fable3 sessions retry-looping menu-flow with the same timeout
   failure, which itself keeps the VM loaded). Workaround shipped in my harness:
   `node tools/capture-map.js shared <scenario ...>` runs the exact `capture.js` scenarios
   with a 300 s per-action budget. Request to Opus 4: raise the harness default
   (`page.setDefaultTimeout`) or read it from an env var.
