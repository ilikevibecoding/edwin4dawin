# WP-012 — Materials & Props (Fable 3)

Status: complete. Part A (procedural PBR material system) and Part B (prop library, placement,
signage, decals, storytelling) are implemented, placed, and verified: full room screenshot tour,
hero orbits, nav sweep with props, and the playability scenarios (combat + escort-real pass;
menu-flow caveat below). Everything is procedural — no external asset files.

## Part A — Procedural PBR texture & material system

New file `src/materials/textures.js`:

- Deterministic RNG (`mulberry`) + tileable FBM value noise; every generator is seeded so the
  build is reproducible run-to-run.
- All maps are `THREE.CanvasTexture`, `RepeatWrapping`, anisotropy 1, `LinearMipmapNearestFilter`
  (minimal SwiftShader sampling cost in QA; visually indistinguishable at our texel density).
  Color maps sRGB, normal/roughness maps linear. Normal maps derive from procedural heightfields
  via a wrap-around Sobel helper, so every set tiles seamlessly.
- 20 texture-set generators at 256–512 px, ~128–430 px/m (per-set tile size + look notes in
  `docs/manifest/materials.json`): drywall (orange-peel + scuff), plaster, acoustic ceiling tile
  (perforations + 0.6 m grid), commercial carpet (two colorways + worn traffic-lane variant),
  vinyl, ceramic tile w/ grout, raised access floor, broom-finish concrete (+ painted variant),
  ribbed steel deck, wood/veneer/laminate, brushed metal, painted metal (clean + scuffed), snow
  w/ sparkle (roughness dropouts), asphalt, brick, woven fabric, exterior panel, rubber,
  cardboard.
- NO baked lighting in any base color; all shading comes from the normal/roughness response.

`src/materials/index.js` upgrades every existing material name in place (`getMaterial(name)` API
unchanged — nothing else in the game had to change) and adds new names for the prop pass
(veneer, laminateWhite, metalBlack, chrome, mirror, screenOff, ledGreen/Red/Amber/Cyan, lampWarm,
plantLeaf, soil, upholsteryWarm, plasticGray). Tiled materials carry `userData.tileM`;
`placeProps()` retrofits world-space UVs onto all static map geometry via `worldUVs()`
(`retrofitWorldUVs` in `src/props/index.js`), skipping doors/shutters and non-axis-aligned
transforms so nothing swims when it moves. Verified in the room tour: tiling scale is consistent
across rooms and no shimmer at 720p/900p (mipmapped).

Wear variants where they read: scuffed drywall base bands (decal), carpetWorn traffic lanes,
concrete vs concretePaint, scuffed painted metal vs clean aluminum.

## Part B — Prop library + placement

New modules (all under exclusive Fable 3 ownership):

- `src/props/kit.js` — `Bucket` (per-material geometry merge via
  `BufferGeometryUtils.mergeGeometries`), `Kit` (geometry + collider emission), `Frame` (local
  coordinate frames with yaw + `sub()` nesting). All static props merge into three zone buckets
  (`props-gs` ground service, `props-gp` ground public, `props-f1` upper) so a fully furnished
  floor costs ~1 draw per material per zone while frustum culling still works. A cached
  chamfered-box primitive (44 tris) gives slabs believable edge bevels — no razor edges.
- `src/props/library.js` — ~90 parametric builders, each registered via
  `registerAsset(id, {name, category, agent:'Fable 3', build})` (full ID list in
  `docs/manifest/props.json`); real-world dimensions from the visual bible; material separation
  everywhere (metal legs / laminate tops / fabric seats / rubber feet).
- `src/props/signage.js` — two 1024 px canvas atlases: `signs` (print) and `screens` (emissive
  UI), so all signage/screens in the level cost 2 materials. All text original: department
  signs, room plates, directional arrows, safety poster, evac diagram, notice boards (shift
  swap, canteen menu), whiteboards, monitor/laptop UI (4 variants), security camera grid,
  conference slide ("Winter Logistics Review"), vending front ("Polar Bites"), rack LED banks,
  copier panel, shipping labels, van livery ("NORTHSTAR RESPONSE — Priority Logistics Unit 07"),
  brochures ("Northstar Dynamics"), ID badges, calendar, photos.
- `src/props/decals.js` — single 512 px alpha atlas, one material with `polygonOffset(-2,-2)` +
  `depthWrite:false`; each decal is one quad merged into its zone bucket. Kinds: carpet wear,
  floor dirt, oil, water stains, snow-melt puddles + boot-print tracks at the entrance, wall
  scuffs, cable runs, removed-sign residue, scattered papers, painted floor lines.
- `src/props/placement.js` — per-room layouts for all 22+ rooms driven by `src/map/layout.js`
  rects: garage (van hero + workbench + cones), loading (pallets/crates/drums/dock
  bumpers/hand truck/ladder), mech (HVAC, ducts, pipes+valves, transformer, panels), server
  (6 LED racks + network cabinet + UPS + cable trays + hostage-holding evidence), IT, janitor
  (cart/mop/shelving), break room (kitchen run w/ sink+faucet, fridge, microwave, coffee,
  kettle, vending hero, water cooler, cafe tables, notice board), restrooms (vanities+mirrors,
  stalls, toilets, dryers, dispensers, drains), copy (copier hero + shelving + supplies), sec
  office (occupied guard post: camera wall, terminal, coffee, headset), lobby (reception hero +
  struggle storytelling: tipped chair, scattered papers, dropped briefcase), waiting lounge
  (sofas + coffee table + brochures), plaza/vestibule (floor mats, cones, snow-melt decals),
  upper floor: open-office cubicle field (2x2 panel pods, per-seat variation), print/supply,
  conference (table+chairs, emissive display, projector, whiteboard), records (rolling archive
  racks), exec wing (exec desk + assistant + hostage evidence), HR, storage, quiet room,
  mezzanines.

### Gameplay integration

- Colliders: 350 prop colliders (`world.add({min,max,material,tag:'prop'})`) for everything
  knee-height+; small clutter has none.
- Cover along routes: cubicle pods, lobby planters + reception desk, loading crates/drums,
  server racks.
- Walkways kept >= 0.9 m; no doorway blocked; patrol waypoints have >= 0.4 m clearance.

## Playability scenarios

- `escort-real`: PASS, zero console errors — hostage B followed the full route
  exec-corr -> stair-a1 -> lobby -> sec -> service corridor -> garage, 0 suppressed-teleport
  warnings (`/tmp/play2.log`, shot `artifacts/shots/escort-real--*.png`).
- `combat`: PASS, zero console errors.
- `menu-flow`: fails in this VM on `page.screenshot` (Playwright's default 30 s budget in
  tools/capture.js), never on game logic and with zero console errors in every attempt (menu
  clicks and deploy all work). Measured with `tools/_probe-shot.mjs`: one 1600x900 compositor
  screenshot of the title scene (exterior orbit camera — the most expensive view in the game)
  takes 19–177 s depending on VM contention. To rule out this work package as the cause I added
  a `?notex=1` kill switch (materials/index.js) that serves flat-color materials: the untextured
  title shot is just as slow (26/146/122 s vs 19/69/69 s textured back-to-back), so texture
  sampling is NOT the bottleneck — raster/geometry volume and shared-VM contention are. My own
  harness sidesteps the compositor entirely by reading the WebGL canvas in-page (`toDataURL`,
  completes in seconds — see `tools/capture-props.js shot()`); recommend the lead bumps the shot
  timeout or adopts the canvas read for shared-VM runs.

## Performance

`window.__qa.perf()` at worst-case cameras (includes shadow pass, whole scene: map + entities +
props + viewmodel):

| Camera | draw calls | triangles |
|---|---|---|
| lobby | 811 | 296,628 |
| cubes | 1,043 | 326,932 |
| garage | 675 | 272,160 |
| mezz-south | 1,199 | 360,624 |
| plaza (exterior, worst) | 1,383 | 381,688 |

Prop share (scene-graph audit, `tools/_probe-stats.mjs`): **99 meshes / 75,406 tris** for the
entire furnished level — the merge-bucket strategy holds (~30 meshes per zone, one per
material). For comparison the base map is 200 meshes / 50k tris and entities 445 meshes / 86k
tris; the scene-wide draw-call pressure is dominated by entities + map + double-draw from the
shadow pass, not by props. If the team needs to claw back budget, entity merging is the lever.

## Known issues

- `menu-flow` screenshot-budget flake on the shared VM (see Playability above); game logic and
  console are clean.
- Doors keep flat paint materials (no wood/wear texture): default box UVs stretch wear patterns
  on the 0.05 m door edge; texturing them needs per-face UVs on the door builder (Fable 2's
  file), so left tuned-flat by agreement with the API boundary.
- The decal atlas is shared by all zones; a decal-heavy future map could want a second atlas
  page.
- Restroom mirrors are low-roughness metal (per spec) — they read as mirrors only with
  glancing light; a real reflection probe was out of scope.
