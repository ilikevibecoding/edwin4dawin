# LEGO Star Wars — a procedurally built three.js cinematic

Everything on screen is generated by code. There are no models, textures, images
or audio files checked into this repo except the pre-rendered narration WAVs
(themselves synthesized locally). Bricks are placed by hand in stud coordinates,
the score and sound effects are synthesized with the Web Audio API, and the 2D
artwork is emitted as SVG strings.

```
src/
  core/      engine, render loop, timeline, camera rig, materials, RNG
  lego/      the parts bin: kit.js (bricks), minifig.js, characters.js, ships.js, props.js
  world/     environments: space.js, tatooine.js, corridor.js, deathstar.js
  fx/        effects.js — bolts, explosions, engine trails, smoke, holograms
  audio/     score.js, sfx.js, engine.js, narration.js
  svg/       assets.js — logo, crawl, insignia, HUD, title cards
  scenes/    one module per sequence of the film
tools/       shot.mjs (headless preview screenshots), render.mjs, vo.mjs
```

## Non-negotiable conventions

**Units.** Everything is in LEGO stud units. `1.0` = one stud pitch (8 mm on a
real brick), `PLATE = 0.4`, `BRICK = 1.2`. A minifigure is `4.8` tall.

**Axes.** `+Y` is up. Builds face `-Z` — the three.js forward axis, so
`object.lookAt(target)` and `+Z` = "behind" both work without correction. Ships
fly nose-first toward `-Z`. Minifig joints rotate *positive = forward*.

**Placement.** Brick coordinates are the **centre of the footprint** at the
**bottom** of the part. `kit.brick(0, 0, 0, 4, 2, C.red)` sits a 4x2 brick on the
ground centred on the origin. Builds are symmetric about `x = 0`; use
`kit.sym(s => ...)` to write one half and get both.

**Determinism.** Never call `Math.random()` anywhere in `src/`. The offline video
renderer steps the same timeline as live playback and must produce identical
frames. Use `makeRng('some-name')` from `src/core/rng.js`.

**No per-frame allocation.** Update functions run 30–60 times a second under a
software rasteriser. Hoist vectors, reuse arrays, never build geometry in an
update.

**Software rendering.** This machine has no GPU; Chrome runs SwiftShader. Keep
part counts sensible (a hero ship: under ~1500 placements; background props:
far fewer), avoid huge transparent overdraw, and prefer `Kit` batching over
loose meshes.

## The parts bin — `src/lego/kit.js`

`Kit` collects part placements and batches them into one `InstancedMesh` per
(geometry, material) pair, so a 3000-brick ship costs a few dozen draw calls.

```js
import { Kit, PLATE, BRICK, STUD_R } from '../lego/kit.js';
import { C, SW } from '../lego/palette.js';
import { FINISH } from '../core/materials.js';

const kit = new Kit('xwing');
kit.brick(0, 0, 0, 6, 4, C.lightBluishGray);        // x, y, z, width, depth, colour
kit.plate(0, BRICK, 0, 6, 4, C.red);                // 0.4 tall
kit.tile(0, BRICK + PLATE, 0, 2, 2, C.black);       // smooth top, no studs
kit.block(0, 0, -4, 2, 2, C.darkBluishGray);        // brick height, studless
kit.box(0, 2, 0, 1.5, 0.6, 3.2, C.white);           // free-form, world units
kit.slope(0, 1.2, -3, 4, 2, C.red, { h: BRICK });   // falls from -z back to +z front
kit.poly(0, 0, 0, [[-8,0],[8,0],[0,-22]], 0.8, C.hullGray);   // (x,z) polygon extruded up
kit.profile(0, 0, 0, [[-2,0],[2,0],[2,1],[-2,2]], 6, C.white); // (z,y) profile extruded along x
kit.cyl(0, 0, -6, 0.6, 2.4, C.flatSilver, { axis: 'z', seg: 16 });
kit.cone(0, 0, -8, 0.7, 0.2, 1.5, C.gunmetal);
kit.sphere(0, 3, 0, 0.9, C.transLightBlue, { finish: FINISH.trans });
kit.torus(0, 1, 0, 1.2, 0.2, C.black);
kit.stud(1, 2, 3, C.red);                            // lone stud, for greebling

kit.push().translate(2, 0, -3).rotY(0.4);            // transform stack
kit.brick(0, 0, 0, 2, 2, C.yellow);
kit.pop();

kit.sym((s) => kit.brick(s * 3, 0, 0, 2, 4, C.red)); // mirrored halves
kit.point('engineL', -3, 1, 6);                      // named attach point
kit.merge(otherKit);                                 // fold in a sub-assembly
kit.add(someObject3D);                               // fold in a non-brick object

const group = kit.build();          // THREE.Group
group.userData.points.engineL;      // THREE.Vector3, in the group's local space
group.userData.brickCount;
```

Per-part options: `{ h, studs, bevel, rot, scl, finish, opacity, emissive,
castShadow, receiveShadow, seg, axis, renderOrder }`. `rot` is a Y angle or
`[rx, ry, rz]`.

Finishes live in `src/core/materials.js`: `plastic` (default), `matte`, `metal`,
`trans`, `glass`, `glow` (emissive, drives the bloom pass), `sand`. Colours live
in `src/lego/palette.js` — `C` is the LEGO palette, `SW` the film-specific
shorthands (`SW.saberRed`, `SW.sand`, `SW.r2Blue`, …).

## Minifigures — `src/lego/minifig.js`

```js
import { createMinifig, FACES, drawFace, createBlaster, FIG } from '../lego/minifig.js';

const fig = createMinifig({
  skin: C.yellow, torso: C.white, arms: C.white, hands: C.black,
  legs: C.white, hips: C.white,
  face: FACES.determined, faceKey: 'determined',          // faceKey must be unique per print
  torsoPrint: (g, w, h) => { /* canvas 2d */ }, torsoKey: 'stormtrooper',
  headgear: () => buildHelmet(),                          // Object3D parented to the head
  cape: { color: 0x141414, w: 1.8, h: 2.6 },
  accessoryR: createBlaster({ long: true }),              // parented to the right hand
});

fig.userData.pose({ armL, armR, elbowL, elbowR, legL, legR,
                    headTurn, headTilt, lean, twist, crouch, armLOut, armROut });
fig.userData.walk(t, speed);       // full walk cycle including the LEGO side-to-side rock
fig.userData.idle(t, phase);
fig.userData.update(t, dt);        // capes etc. — call every frame
fig.userData.parts;                // { head, neck, torso, armL, armR, handL, handR, legL, legR, ... }
```

`faceKey` / `torsoKey` / `legKey` are texture cache keys. Two different prints
sharing a key will silently render the same artwork.

## Exhibits — how you check your work

Every buildable module exports an `EXHIBITS` map so it can be rendered in
isolation on a baseplate:

```js
export const EXHIBITS = {
  xwing: () => buildXwing(),
  'xwing-open': () => buildXwing({ sFoils: true }),
};
```

Then, from the repo root:

```bash
node tools/shot.mjs xwing                       # -> tmp/shots/xwing.png
node tools/shot.mjs xwing tie --az 250 --el 30 --w 900 --h 650
node tools/shot.mjs --list                      # every registered exhibit
```

The tool starts Vite if it is not already up, renders headlessly, prints the
part count and any page errors, and writes a PNG. **Look at the PNG.** Nothing
in this project is finished until it has been seen.

An exhibit may return an object whose children carry `userData.update(t, dt)`;
the harness calls those every frame, which is how animated builds are checked.

## Runtime pieces the film expects from a build

Anything that animates exposes `userData.update(t, dt)` and, where useful, named
sub-objects on `userData` (`turrets`, `engines`, `canopy`, `muzzle`, …) plus
`userData.points` from the kit. Keep builders pure: same arguments in, same
geometry out, no global state.
